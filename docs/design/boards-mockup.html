ADR006 · proposed

Boards mockup: thin custom UI

A clickable sketch of the Ideas, Tasks, Projects and Decisions boards as ADR006 proposes them: server-rendered columns of status, with a small script for dragging and moving. The data is sample data. Saving, syncing and conflicts are simulated.

Try dragging a card by its ⠿ grip, or use Move to…. Move a ready idea to Transplanted, an active project to Completed or Archived, or a decision to ACCEPTED or SUPERSEDED, to see the consequential paths. On Tasks, look for the red blocked by and green unblocked chips. Switch to iPhone to see the 375 px layout.

Ideas

What the mockup shows

Columns are statuses

Each column is one status from spec §7, in lifecycle order. Nothing else decides where a card sits, so a card moved on the Mac lands in the right column after the next fetch.

Terminal columns (Composted, Transplanted, Cancelled, Archived) start folded. Click the strip to open one.

Only allowed moves

While you drag, columns the lifecycle forbids are dimmed and refuse the drop. Move to… lists only allowed targets. The write service rejects anything else anyway; the UI just doesn't offer it.

Drag by the grip

Cards drag only by the ⠿ grip, which has touch-action: none. The rest of the card scrolls the board normally on a phone, and tapping the title opens Record detail.

Move to… works everywhere

A native <select> on every card. On iPhone it opens the system picker. It is also the keyboard and screen-reader path. Without JavaScript the boards can be read but not changed.

Sync indicator

Every move shows Saving…, then committed with the short commit SHA, or pending when GitHub can't be reached. The top bar sums it up for the whole page (§12.2).

409 conflict

If the file changed since the page was rendered, the server rejects the move. The dialog shows base, current and yours for the fields that differ, and offers to move anyway on the current version or keep it (§8.4).

Consequential moves

Ready → Transplanted starts the promotion wizard instead of moving the card (§10). A project from Active to Completed or Archived, and a decision to ACCEPTED, SUPERSEDED or EXPIRED, open the confirmation with the diff and a passkey check (§9.2).

Blocked, two ways

The Blocked column is the status, set by hand. Separately, a red blocked by chip shows open blocks links in any column, and moving such a task to In progress or Done asks first.

Moving a blocker to Done also moves the Blocked tasks it was the last open blocker of to Ready, in the same commit; Move to… shows it as “Done (+1 unblocked)”. Try it with OS-T-2B7KC. If a blocker was cancelled instead, a green unblocked chip offers a one-tap move.

Decisions board

Columns are the upper-case ADR states. A move rewrites both the frontmatter status and the body's * Status: line. SUPERSEDED is only allowed once a newer decision supersedes this one; otherwise the drop offers to draft that decision.

Changes from the Mac

The server fetches every 60 s. The page asks whether the board changed when it becomes visible and every 60 s, and offers a refresh, or swaps the board in place if no move is in flight.

No order within a column

Cards sort by updated, newest first. Manual ordering would need a stored position, which would mean an x- key in every file. Left out of the first version.
